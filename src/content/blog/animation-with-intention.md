动画最容易被滥用。一旦学会了怎么做，就忍不住到处加：淡入、滑动、弹跳、旋转。结果页面像一场永不落幕的魔术表演，用户反而记不住重点。

## 动画应该回答三个问题

每次加动画之前，我会问：

1. **它从哪里来？** 一个从右上角滑入的通知，暗示它来自状态栏。
2. **它要去哪里？** 一个展开后收起的卡片，暗示层级关系。
3. **它有多重要？** 越重要的变化，动画越应该克制。

如果三个问题都答不上来，那大概只是想炫技。

## 时长比曲线更重要

很多人纠结于缓动曲线的数学参数，却忽略了时长。我的经验值：

- 微交互（按钮、图标）：150–250ms
- 内容切换：300–450ms
- 页面级的转场：不超过 600ms

超过这个范围，用户会开始等待动画结束，而不是阅读内容。

```css
.card {
  transition: transform 320ms cubic-bezier(0.16, 1, 0.3, 1);
}
.card:hover {
  transform: translateY(-4px);
}
```

## 连续性与留白

动画也需要留白。如果页面上所有元素都在动，就等于什么都没动。我会刻意让大部分元素保持静止，只在关键路径上安排一到两个动画。

<Callout type="tip" title="一个小技巧">
把动画错开 60–100 毫秒，列表项会像波浪一样依次出现。这种细微的节奏感比同时出现更自然，也更容易被感知为「有序」。
</Callout>

## 尊重选择

最后再说一次：**永远支持 `prefers-reduced-motion`**。这不是对少数用户的让步，而是对「界面应该服务人」这件事的基本尊重。

动画的终点，是让人忘记动画的存在。
